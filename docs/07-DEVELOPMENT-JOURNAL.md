# ASTRAYON 개발 저널

2026-10-16 정리. 목표는 **격자에서 기체를 이동하고 공격을 선택하면, 약 20초의 전투와 결과를 거쳐 맵으로 돌아오는 첫 교전**이다. 아스트레이온·옵시디언 각 한 기, 라이플·블레이드 러시 두 분기를 구현했다.

이 문서는 현재 보존된 기획 문서, 원화와 생성 프롬프트, 구현 파일, 테스트, 브라우저 캡처를 근거로 개발 과정을 정리한다. 과거의 실행 소스 전체를 단계마다 저장한 스냅샷은 없다. 공개 저장소의 단계별 커밋은 **현재 보존 자료를 기능·제작 순서로 나누어 정리한 기록**이며, 당시 커밋을 복원한 것이 아니다. 날짜를 소급하지 않는다. **중간 커밋은 부분 구성이고 빌드 가능한 버전이 아니며, 전체 게임은 최종 구성을 기준으로 검증했다.** 아래 개발 단계 번호는 설명 순서이고 커밋 해시나 완료 날짜를 뜻하지 않는다.

공개 이력은 ① 기획·사용자 레퍼런스 ② 빌드 설정·전투와 전술 상태·테스트 ③ 초기 원화·가공 도구·기존 자산 ④ SD 소재·리그·접합 좌표 ⑤ UI·맵·음향·타임라인 ⑥ 전신 모션·전장 효과·검수 도구와 테스트 ⑦ README·QA·개발 기록·CI 순서로 정리한다. 이 순서는 현재 구현을 이해하기 위한 묶음이며 과거 작업 시간을 재현하지 않는다.

## 1. 기획과 첫 20초 범위

처음 받은 자료는 설정화·포스터 6장과 제작 문서였다. 설정화에는 설명과 장식 문구가 합쳐져 있어 그대로 전투 스프라이트나 완성 애니메이션으로 사용할 수 없었다.

전체 약 3분 제안에서 먼저 공격 선택 → 주인공 컷인 → 준비 → 첫 공격 → 라이벌 컷인 → 충돌 → 피해 → 결과의 20초를 분리했다. 파일럿·기체의 식별 특징을 유지하고, 라이벌의 밝은 갈색 머리와 비대칭 반쪽 가면을 기준으로 삼았다. 이후 사용자가 격자 이동과 SD 기체를 명시하면서 초기 문서의 풀 사이즈·격자 생략 제안은 변경했다.

- 근거: [제작 방향](01-CREATIVE-BRIEF.md), [쇼트 구성](02-SCENE-AND-SHOTLIST.md), [아트 인계](03-ART-AND-ASSETS.md), [SD 방향 변경](06-SD-MOTION-DIRECTION.md).
- 보존: 원본 레퍼런스는 수정하지 않고 게임 자산을 별도 제작했다. [원본 무결성 기록](../web/qa/reference-integrity.json)에 6장 해시 검사를 남겼다.

공개 자료의 레퍼런스 6장은 사용자가 제공한 이 프로젝트의 설정화·포스터다. 대화에서 동작과 비례 참고용으로 첨부한 실제 슈퍼로봇대전 캡처는 저장소에 포함하지 않는다.

## 2. 전투 상태와 격자 전술

전투 영상만 재생하는 선택이 되지 않도록 판정과 렌더링을 분리했다. 명령을 확정할 때 자원과 피해를 계산하고, 액션·세션 식별자로 중복 명령이나 이전 재생의 콜백을 차단했다. 자연 종료와 스킵은 같은 결과를 한 번만 적용한다.

추가 요청에 따라 도트 기체, 최대 5칸 이동, 장애물·적 점유 칸을 피하는 BFS 경로, 이동 취소와 무기별 사거리를 구현했다. 맵 복귀 시 이동 위치와 전투 자원을 유지한다. Next.js·TypeScript가 UI와 상태를, PixiJS가 전장을, GSAP의 단일 시계와 Web Audio가 재생·음향 제어를 담당한다.

실제 실행에서는 첫 애니메이션 프레임 시각이 클릭 시각보다 빠를 때 이동 경과 시간이 음수가 되어 경로 인덱스가 −1이 되는 오류가 발견됐다. 경과 시간을 0 이상으로 제한하고 음수·중간·완료 경계 검사를 추가했다. 음향의 비동기 정지·재개가 뒤늦게 완료되어 스킵한 전투를 되살리지 않도록 취소와 세션 검사도 보강했다.

- 구현: [전투 상태](../web/src/game/state/battle.ts), [전술 규칙](../web/src/game/state/tactics.ts), [타임라인](../web/src/game/timeline/AttackDirector.ts), [음향](../web/src/game/audio/BattleAudio.ts).
- 검증: [상태 테스트](../web/tests/battle.test.ts), [전술 테스트](../web/tests/tactics.test.ts), [타임라인 테스트](../web/tests/director.test.ts), [음향 테스트](../web/tests/audio.test.ts). 중복 명령 100회, 이전 세션, 스킵·자연 종료, 이동·사거리·자원 유지 등을 검사한다.

## 3. 초기 원화와 한계 확인

초기 애니매틱은 구조와 타이밍을 확인하는 임시 그림이었다. 이후 투명 기체 8포즈와 배경·충돌 원화를 새로 만들어 적용했다. 하지만 정지 포즈 교체와 평행 이동이 중심이라, 무기를 실제로 휘두르거나 맞은 뒤 무게를 잃는 동작은 충분히 읽히지 않았다. 이 상태를 최종 애니메이션으로 간주하지 않고 다음 제작의 출발점으로 남겼다.

- 보존: [초기 SVG](../web/source-art/legacy-animatic/), [원화와 프롬프트](../web/source-art/), [v2 검수 기록](../web/QA-v2.md).
- 상태: 이전 기체·충돌 원화는 현재 전투에서 사용하지 않는다. 이전 궤도 배경은 전술 맵과 로딩 실패 시 예비 배경에 남아 있다.

## 4. SD 16부품과 파일럿 액션 원화

사용자가 제시한 화면에서 큰 머리·짧은 팔다리·선명한 셀 채색 스프라이트와 조종석 액션 표정을 참고했다. 기존 게임의 기체·UI·음악을 가져오지 않고 아스트레이온과 옵시디언을 각각 16개 투명 부품으로 새로 제작했다. 전용 파일럿 액션 컷인 2장과 전장 배경도 제작했다.

생성 원본에서 알파 연결 영역을 분리하고 비례를 유지한 WebP로 가공했다. 팔·다리·몸통의 부모/자식 관절을 연결하고 무기를 손에 부착했다. 빔은 총구, 검광은 칼날, 추진 효과는 부스터 좌표에서 나온다. 파일럿 그림은 통째로 좌우 반전하지 않아 가면 방향을 보존한다.

- 보존: [SD 원본·프롬프트](../web/source-art/sd-v3/), [가공 스크립트](../web/scripts/prepare-sd-art.mjs), [실제 게임 자산](../web/public/game/sd/), [이미지 검사](../web/qa/sd-v3/art-check.json).
- 구분: 신규 원화는 실제 사용 소재다. 현재 움직임은 분리 부품의 관절 애니메이션이며, 매 프레임 새로 그린 도트 작화나 완성 영상은 아니다.

## 5. 실제 관절 위치 교정

첫 조립에서는 공통 앵커와 임의 길이를 사용해 머리·팔·허리·다리가 어긋났다. 생성 원화의 관절 위치가 두 기체와 앞·뒷부품마다 달랐고, 몸통·골반과 상완·전완에는 중복된 관절 그림도 있었다. 부품을 키우거나 원형 덮개로 가리는 대신 실제 투명 이미지를 확대해 연결점을 다시 측정했다.

목과 몸통, 허리와 골반, 어깨·팔꿈치·손, 고관절·무릎을 기체별 좌표로 연결했다. 가까운 팔의 위치를 교정하고, 골반 아래에 몸통과 양다리를 함께 두었다. 라이플은 탄창이 아닌 손잡이를 쥐게 하고, 손잡이를 유지한 손목 조준으로 총신 방향과 빔 방향을 일치시켰다. 칼날과 장갑의 실제 접촉 위치도 다시 맞췄다.

- 구현: [부품별 좌표](../web/src/game/data/rig-layout.ts), [관절 리그](../web/src/game/scenes/SDMechaRig.ts).
- 근거: [아스트레이온 부품 비교표](../web/qa/sd-v3/audit/hero-parts.png), [옵시디언 부품 비교표](../web/qa/sd-v3/audit/rival-parts.png).
- 검증: 실제 32개 WebP 크기로 리그를 구성해 원화 연결점의 일치, 카메라 변환 뒤 접촉 보존, 총신과 빔 방향을 검사한다. 장갑에 가려진 허리·고관절 좌표는 의미적 추정이 포함되어 있어 최종 모델 시트 검수를 대체하지 않는다.

## 6. 전신 가중 모션과 최종 QA

접합이 맞아도 모든 관절을 같은 속도로 보간하면 정지 포즈 사이를 이동하는 느낌이 남았다. 검격은 골반·다리의 하중 이동 → 가슴 회전 → 어깨 → 팔꿈치 → 손목과 검끝 순으로 가속하도록 바꿨다. 준비 자세에서는 몸을 낮추고, 공격 후에는 관성과 지연 회복을 준다. 피격은 뒤로 밀림과 순간 부양, 무릎 붕괴, 자세 회복으로 이어진다.

발바닥 접지는 리그의 `apply()` 안에서 계산한다. 효과 레이어만 따로 위치를 고치는 방식이 아니므로 테스트와 화면의 무기 접점이 동일하다. 그림자·먼지는 실제 발바닥을 따르고, 검 잔광은 이전 시각의 실제 칼날 위치로 만든다. 모든 움직임은 같은 20초 시계에서 계산해 정지·탐색·재시작으로 변환이 누적되지 않는다.

- 접촉 시각: 첫 패링 **6.62초**, 본 검격 **13.50초**, 반격 **14.55초**. 일반 모드에서 접촉을 90ms 유지하며 효과 감소 모드에서는 이를 제거한다.
- 무게감: 주 타격 후 적이 120px 이상, 반격 후 아군이 70px 이상 밀린다. 착지·무릎 붕괴 때 적 골반은 회복 자세보다 약 26px 낮아진다. 수치는 논리 전장 1600×900 기준이다.
- 회귀 검사: [모션 테스트](../web/tests/motion.test.ts)는 관절 연결, 접촉 3곳의 30px 이내 거리, 조준, 순차 가속, 피격 인과, 실제 발바닥 접지를 다룬다. 별도 1ms 간격 검산에서도 양 분기와 효과 감소 모드의 발 침투·관절 분리는 수치 오차 범위였다.
- 검수 도구: `/review`에서 실제 렌더러를 재생·정지·탐색하고 0.5배속으로 관절과 접촉을 확인한다. 정적 서버가 이 경로를 찾지 못하던 파일 탐색 오류도 수정했다. 검수 페이지는 파일럿·HUD·음향을 포함한 본편 플레이 검사와 구분한다.

### 최종 검증과 화면 증거

최종 코드에서 **33개 테스트, TypeScript 검사, 프로덕션 빌드가 통과**했다. 상태·전술 17개, 음향·타임라인 8개, 모션 8개다. 데스크톱 프로덕션 브라우저에서 맵 이동과 공격을 거쳐 두 무기가 각각 20.00초에 자연 종료하는 것을 확인했다.

## 남은 범위

현재는 맵 한 장과 첫 교전 두 분기의 완결된 데모다. 적 턴 AI, 복수 유닛, 연속 교전, 전체 3분 시나리오의 방어·회피·최종기는 구현 범위 밖이다.

파일럿의 눈·입 프레임, 다른 시점과 원근 변화에 필요한 기체 작화, 접촉 전후 연결 작화는 후속 제작 대상이다. 음향은 Web Audio 합성 데모이며 성우 녹음과 최종 믹싱은 없다. 새 SD 부품의 표면 디테일·장갑 정합성도 최종 디자인 승인을 대신하지 않는다. [소재 상태와 교체 목록](../web/ASSET_REPLACEMENTS.md)에서 실제 사용·교체 완료·미제작을 구분한다.

실제 모바일 GPU·터치, Safari/Firefox, 스크린리더, 스피커 청취·오디오 지연과 장시간 성능은 최종 데스크톱 검수와 별개로 남아 있다. 이전 버전의 반응형 검사 결과를 최신 기체 모션의 전체 기기 지원으로 확대하지 않는다. 공개 저장소 게시, 호스팅 배포, 외부 URL의 실행 확인도 서로 다른 작업으로 기록한다.
