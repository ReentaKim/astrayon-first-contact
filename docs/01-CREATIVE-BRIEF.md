# 01 · 제작 방향

## 사용자가 직접 밝힌 요구

웹 형태의 간단한 게임을 원한다. 현재 만든 기체 세계관을 활용하고, 슈퍼로봇대전 같은 감각을 참고한다. 분량은 애니메이션 한 장면 정도면 충분하다. 짧더라도 강렬한 연출과 애니메이션 컷을 포함해 완성도를 높인다. 실제 구현은 Codex 작업 환경으로 이어가려 한다. 라이벌 파일럿은 주인공과 다르게 생겨야 하고, 얼굴을 반쯤 가리는 가면이 필요하다.

## 제작 제안 — 아직 사용자 확정 사항은 아님

작업명은 **ASTRAYON — 두 개의 하늘**. 붕괴한 궤도도시 외곽, 구조선이 탈출하려는 순간을 배경으로 제안한다. 주인공은 구조선을 지키고, 옵시디언은 그 배가 가져가려는 무언가를 막으려 한다. 둘 다 자기 이유가 있지만 여기서는 설명을 길게 하지 않는다.

> 주인공: “저 배에는 아직 사람이 있어.”
>
> 라이벌: “그래서… 보내줄 수 없는 거다.”

제안하는 작품 길이는 연출과 기본 진행 약 3분, 초회 플레이 약 3~5분이다. 입력을 기다릴 때는 장면의 시간이 멈추므로 개인별로 달라진다. 개발 소요시간을 의미하지 않는다.

## 핵심 경험

**공격 버튼을 누른 내가, 방금 본 장면을 일으켰다는 감각.**

화면 대부분은 16:9 전투 무대다. 대사와 커맨드는 무대 위의 최소한의 오버레이로 표시한다. 긴 소개 페이지, 상시 사이드바, 카드형 대시보드, 스크롤 설명 영역은 넣지 않는다. 파일럿 컷인은 잠깐 시선을 빼앗았다가 즉시 기체 행동으로 이어진다. 주인공의 푸른빛과 라이벌의 붉은빛은 구분에 쓰되, 색상만으로 정보를 전달하지 않는다.

풀 사이즈 기체를 중심으로 연출한다. SD 기체, 대형 격자 전장, 경비기 여러 대는 첫 장면에서 제외하는 안을 제안한다. 슈로대에서 기대하는 커맨드 전투와 HP/EN·파일럿 컷인 감각은 유지한다.

## 플레이 구조

서로 다른 선택 2회와 최종 공격 명령 1회로 구성한다. 첫 선택은 사격으로 거리를 유지할지, 접근전을 걸지 정한다. 두 번째는 라이벌의 반격을 방어할지 회피할지 고른다. 선택 결과는 기체 HP·EN, 조준 상태, 직후 컷의 행동과 후일담 한 줄에 반영한다. 마지막 공격은 남은 자원과 누적 상태를 반영하되 첫 장면의 서사적 종착점은 두 기체의 생존과 라이벌 퇴각으로 통일한다.

빠른 키 입력을 요구하는 QTE는 첫 버전에서 제외한다. 선택 중에는 안전하게 시간을 멈추고, 연출 중에는 명령이 중복 입력되지 않게 한다. 승패를 난수 하나로 결정하지 않는다.

## 우선순위

P0는 캐릭터 일관성, 20초 핵심 전투 연출, 실제 반영되는 선택, 음향 동기화, 끊김 없는 재생이다. P1은 전체 장면 연결, 별도의 공격·피격 컷, 자연스러운 대사 전환, 재플레이 안정성이다. P2는 검수된 짧은 영상 컷이나 성우 음성의 추가이며, 장면이 무음 자막으로도 완결되어야 한다.

원화/영상/음성은 개발 코드와 별도의 제작·검수 대상이다. 코드가 완성되었다고 최종 애니메이션 소재까지 확보된 것으로 보고하지 않는다.
