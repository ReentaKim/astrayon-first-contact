# 04 · 구현과 검수

## 제안 기술 구성

Next.js + TypeScript를 앱의 외곽과 상태 UI에, PixiJS를 전장·기체·효과 렌더링에, GSAP를 쇼트 타임라인에 사용한다. Web Audio를 음향 제어에 사용한다. 설치 시 공식 문서에서 호환되는 안정 버전을 확인하고 실제 설치 버전을 잠금 파일에 남긴다. 특정 구버전의 API를 무검증 복사하지 않는다. 자세한 API 참고는 `05-SOURCES.md`에 있다.

이 한 장면에는 로그인·서버 API·데이터베이스가 필요하도록 설계하지 않는다. 브라우저 상태로 끝까지 플레이되게 만들며, 개발·검수 후 정적 배포 가능 여부를 실제 빌드로 확인한다. Next.js의 서버 렌더링 중에는 브라우저 전용 렌더러와 오디오를 초기화하지 않는다.

앱 기본 위치는 `web/`이다. 다음은 권장 분리이며 파일명이 의무인 것은 아니다.

```
web/src/app/                 # 진입 화면
web/src/components/         # 대화, 커맨드, 접근성 UI
web/src/game/state/         # 순수 상태 전이와 전투 계산
web/src/game/scenes/        # 준비/전투/엔딩 무대
web/src/game/timeline/      # 쇼트와 타임라인 제어
web/src/game/audio/         # 음량 버스, 재생과 정리
web/src/game/data/          # 대사, 무기, 컷별 데이터
web/public/game/            # 최적화된 실제 플레이 자산
web/tests/                  # 상태 및 브라우저 검사
```

## 상태와 연출을 분리

`TITLE → INTRO → CHOICE_ATTACK → ATTACK → CHOICE_RESPONSE → COUNTER → FINISHER_READY → FINISHER → AFTERMATH → END`

상태에는 HP, EN, 선택 이력, 조준 보너스, 현재 액션 ID, 적용 완료 액션 ID를 둔다. 플레이어가 명령을 확정하면 순수 함수에서 합법성을 검사하고 action result를 계산한다. 연출은 그 결과를 보여주는 역할이다. 연출을 건너뛰어도 같은 action result를 한 번만 적용한다. 입력 연타, 타임라인 끝 콜백, 스킵 콜백이 중복 피해를 주면 안 된다.

일시정지는 현재 진행 중인 장면과 오디오를 함께 멈추되 포커스 가능한 재개 버튼은 남긴다. 재시작 시 타임라인, 예약된 콜백, 음원, 키 입력 구독을 폐기하고 새 세션 ID를 발급한다. 이전 세션의 비동기 자산 로딩이나 콜백이 새 세션에 영향을 주지 않게 한다. 탭이 숨겨지면 안전하게 일시정지하고 복귀 후 사용자가 재개하도록 한다.

## 최소 게임 규칙 예시 — 밸런스 확정 아님

초기 아스트레이온 HP 6,000 / EN 100, 옵시디언 HP 9,000. 조준 보너스는 0에서 시작한다.

| 선택 | EN 변화 | 아군 HP 변화 | 적 HP 변화 | 조준 보너스 |
|---|---:|---:|---:|---:|
| 첫 공격: 사격 | -20 | 0 | -1,200 | +1 |
| 첫 공격: 접근전 | 0 | -400 | -1,600 | 0 |
| 적 반격 대응: 방어 | 0 | -1,400 | 0 | +1 |
| 적 반격 대응: 회피 | -20 | -600 | 0 | 0 |

최종 공격은 EN 60을 사용하고, 피해는 `6,600 + 500 × 조준 보너스`로 제안한다. 적 HP가 1,000 이하면 퇴각한다. 이 예시의 네 조합 모두 자원 부족 없이 마지막 공격에 도달하며, 아군 남은 HP/EN과 적 피해는 다르게 끝난다. EN·HP 표시의 0 이하/최대값 처리는 명시적으로 구현한다. 이 장면은 숙련도 처벌보다 선택의 감각을 보여주는 첫 대결이며, 별도의 성장·난이도 시스템은 없다.

같은 종료 지점이어도 선택 직후 컷은 실제로 달라져야 한다. 사격은 거리 유지와 빔 궤적, 접근전은 부스터와 검격, 방어는 실드 충돌, 회피는 이동으로 보여준다. 모든 선택이 같은 영상을 재생하고 숫자만 바뀌면 미달이다.

## 음향

시작 버튼의 사용자 입력으로 오디오 컨텍스트를 시작/재개한다. 자동 재생 차단이나 음원 로딩 실패에도 무음으로 게임을 끝낼 수 있어야 한다. BGM/SFX/Voice를 분리하고 마스터 음소거를 제공한다. 대사가 있으면 음악을 낮추고, 충돌 앞뒤에는 짧은 소리의 공백과 잔향을 활용한다. 음성을 확보하지 못했다면 자막을 사용하고 시스템 TTS를 최종 성우 연기라고 표시하지 않는다.

## 품질 목표와 자산 관리

16:9 논리 좌표계를 사용하고 실제 화면 크기에 맞춰 비율을 유지한다. PC 브라우저를 우선하며 작은 화면에서도 자막과 버튼이 잘리지 않게 한다. 모바일은 우선 가로 보기 안내로 범위를 제한할 수 있다. 실제 확인 전에는 모든 기기 지원을 주장하지 않는다.

60fps를 목표로 삼되 보장하지 않는다. 대표 기기·브라우저·픽셀 비율·효과 단계와 함께 측정한다. 원본 포스터 6장을 게임 시작에 모두 로딩하지 않는다. 다음 컷에 필요한 파일은 미리 불러오고, 실패 시 재시도 또는 안전한 대체 컷을 제공한다. 레퍼런스 전체 크롭을 반복해 쓰는 단계는 애니매틱으로 표시하고 최종 화면 검수에서 통과시키지 않는다.

## 검수 체크

### 플레이·안정성
- [ ] 처음부터 엔딩까지 4개 명령 조합이 모두 진행된다.
- [ ] 선택별 HP/EN·조준·즉시 연출이 달라진다.
- [ ] 버튼 연타, 스킵, 컷 종료가 결과를 중복 적용하지 않는다.
- [ ] 일시정지/재개 시 영상·음향·자막의 상태가 어긋나지 않는다.
- [ ] 무음, 음원 로딩 실패, 이미지 로딩 실패의 처리가 존재한다.
- [ ] 3회 연속 재시작에서도 이전 효과와 음원이 남지 않는다.
- [ ] 탭 전환 후 복귀했을 때 이야기가 이미 끝나 있지 않는다.
- [ ] Enter/Space 등 키보드로 커맨드와 재생을 조작할 수 있다.

### 작화·연출
- [ ] 라이벌의 머리·얼굴·반쪽 가면이 04의 큰 초상과 일관된다.
- [ ] 가면의 해부학적 좌우가 쇼트 사이에 바뀌지 않는다.
- [ ] 준비·공격·충돌·피격 원화/동작이 구별된다.
- [ ] 속도감이 화면 흔들림만으로 구성되지 않는다.
- [ ] 문구가 들어간 설정화를 통째로 전투 스프라이트로 쓰지 않는다.
- [ ] 효과를 줄이는 모드가 있으며 자막과 상태 정보를 읽을 수 있다.
- [ ] 음성 없이도 인물의 행동 이유와 장면의 시작·끝을 이해할 수 있다.

### 개발 보고
- [ ] 실제 설치된 의존성 버전과 잠금 파일이 있다.
- [ ] 타입 검사와 프로덕션 빌드의 실행 결과가 있다.
- [ ] 전투 상태 테스트가 있다.
- [ ] 가능한 환경에서 브라우저를 열어 대표 컷과 4개 경로를 확인한다.
- [ ] 검증하지 못한 브라우저·성능·배포는 미확인으로 보고한다.
- [ ] 임시 이미지·미확보 영상·미확보 음성 목록을 완료 항목과 분리한다.

## 확장 순서

첫 번째는 위의 핵심 20초 공격 루프다. 두 번째는 장면 전체와 네 명령 조합 연결이다. 세 번째는 최종 원화·음향 교체와 연출 다듬기다. 네 번째는 실제 배포 빌드와 링크 확인이다. 공개 배포는 사용자 승인 후 수행한다. 여기 적힌 것은 작업 순서이지 소요시간 약속이 아니다.
